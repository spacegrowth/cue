## What this can't see

The analysis reads the source with `syn`; it doesn't type-check it. So:

- **Method calls are resolved by receiver type only where the type is written down**: `self`, a parameter
  or `let` with a type annotation naming a crate type, or a field of one. Any other receiver resolves only
  when exactly one crate type has a method of that name and it isn't a common standard-library name
  (`get`, `insert`, `lock`, …; the list is `STD_METHODS` in `xtask/src/parse/resolve.rs`). Otherwise the
  call is counted as unresolved (the count is in the summary) and not followed.
- **Trait objects and generic calls** (`dyn Trait`, `T: Trait`) aren't followed; neither are function
  pointers or closures stored in a struct, a static or a collection and called later. A closure bound to a
  local name is followed where it's called or passed; one passed to a crate function is followed into
  that function's calls of the parameter (in line, or on a thread when it spawns it); one it never calls
  is treated as run later, under no lock.
- **Macros**: arguments of a macro are read when they parse as a comma-separated list of expressions
  (`format!`, `vec!`, `assert!`, …); others (`json!({..})`, `matches!`) are skipped, calls inside them too.
- **Lock lifetimes follow Rust 2021's drop rules, simplified**: a `let` guard lives to the end of its
  block or `drop(guard)`; an unbound guard to the end of its statement (through a `match`/`if let`/`for`
  body), except a plain `if`/`while` condition. A guard moved into a function, returned, or kept in a
  struct isn't tracked past that point. Two locks with the same name are one node (a lock per session,
  like the typing gates, is one).
- **Name resolution** follows `use`, `use …::*`, `self`/`super`/`crate` and inline modules; types are
  known by their last path segment, so two types of one name share their methods.
- **Effects** are what a call's path says: `std::fs`/`tokio::fs`, `Path` methods that stat (`exists`,
  `metadata`, …), `crate::db::*`, `Command::new`, `UNUserNotificationCenter`, `SMAppService`, Unix
  sockets. Anything reached only through an unresolved call or an outside crate's internals is missed.
